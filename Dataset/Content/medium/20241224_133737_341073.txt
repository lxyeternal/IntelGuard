In open-source software’s tangled web of software dependencies, developers often overlook the potential hazards lurking within software dependencies. A recent investigation by Mend has brought to light a particularly intriguing case involving an abandoned RubyGems package, ‘gemnasium-gitlab-service’, demonstrating the dangers of neglecting dependency management.
Unpacking the Incident
In the realm of Ruby, a ‘gem’ serves as a packaged library or code that developers can seamlessly weave into their projects, where each gem can add a unique layer of functionality to an application.
One such gem, ‘gemnasium-gitlab-service’, originally created by Gemnasium and later maintained by GitLab following an acquisition, was abandoned after GitLab decided to discontinue its use.
Under ordinary circumstances, it would end at that. Developers relying on the gem would either persist with the final available version or migrate over time toward an alternative.
However, the story took a twist when an unidentified entity noticed that the gem’s name had been abandoned. Seizing this opportunity, they claimed the gem’s name, breathing new life into it. The inherent risk emerges when projects that have not refreshed their dependencies inadvertently pull in this new version under the assumption that it’s a legitimate continuation of the original gem. Now under the control of an unknown actor, this reborn gem could be a Trojan horse, carrying within it malicious code or undesired actions.
A Systemic Threat
The Mend investigation peeled back further layers of this intrigue, correlating data with the npm registry, Node.js’s equivalent of the RubyGems system, they unveiled another package, ‘tomcrypt’, containing harmful code published by the same owner. The package was designed to exfiltrate sensitive user and host information.
This discovery indicates a systemic method used by malicious actors to locate retired or unused open-source package names, claim them, and potentially exploit them. This strategy casts a spotlight on the inherent risks tied to open-source dependencies and underscores the urgency of adopting robust dependency management practices.
A Web of Malicious Packages
Our exploration extended beyond the initially discovered Ruby and npm packages, uncovering a complex web of dependencies and packages across a multitude of different package managers including Pypi as well. All malicious packages were linked somehow to one of the initial npm and Ruby packages. It appears that distributing malicious packages across package managers has become a frequent strategy to maximize potential impact.
Conclusion:
While open-source software provides numerous advantages, it also carries risks that require careful management. It is incumbent upon all developers and organizations to contribute to the security of the software they create and use.
Working together to keep the open source ecosystem safe.
