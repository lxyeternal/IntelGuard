Checkmarx and Phylum reported on a Typosquatting campaign targeting the NPM and PyPi package managers. This campaign targets the popular “requests” package on PyPi and the “discord.js” package on NPM, and includes embedded ransomware. When executed, the ransomware updates the desktop background, encrypts files, and leaves a readme file requesting payment of $100 in cryptocurrency in exchange for the decryption key. Unlike most open-source attacks, the payload is not executed upon installation, but only when the infected function is called, allowing the threat actor to remain undetected by many security scanners. The payload supports multiple operating systems, allowing the campaign to target a wider audience. While NPM has a mechanism for detecting Typosquatting packages, the threat actor was able to bypass it by using different naming techniques.
Technical Analysis
Our Typosquatting and StarJacking engines alerted us on suspicious packages published by NPM user account “randomusernamelol “and PyPi user accounts “cia.gov” and “cookiedid911” which we swiftly reported to PyPi and NPM as we continued to deep dive and analyze the malware.
Impersonating the “requests” Python Package
Python’s requests package is the unofficial champion when it comes to performing HTTP requests. While there are many 3rd party packages trying to help with making HTTP requests easier, the requests package is by far one of the best user experience packages out there, with nearly 50,000,000 weekly installations.

Infects Upon Usage
Upon examining the code of the package, we realized something quite interesting. Unlike what we have normally seen in the past, where the malicious payload is included in the setup.py file or the __init__.py file to run automatically upon download and installation, instead, the malicious payload is hidden inside multiple strategic places and invoked in scenarios where the victim is using the functionality to make HTTP requests as multiple calls to a suspicious “execute” function were added when making HTTP requests.
image: D:/Desktop/malware/IntelliGraph\Dataset\Image\medium\20241224_133738_161941\1b9oK_KLcDXvVMIq7BQNmfA.png
The ”execute” function receives a list of supported operating systems and CPU architectures from the URL “hxxp://<endpoint>/all.txt”.
image: D:/Desktop/malware/IntelliGraph\Dataset\Image\medium\20241224_133738_161941\12DzmKElI1wYCelTwCnbaA.png
It then proceeds to downloading the malware according to the victim’s operating system and CPU architecture.
Impersonating the “discord.js” NPM Package
The attacker was also active on the NPM ecosystem while targeting the popular NPM package discord.js with many Typosquatting attempts while stealing the original project’s description.

Similarly to the Python malicious packages, the attackers chose to invoke the malicious code when the victim is using very specific functionality.

Malware Analysis
We scanned the downloaded files in VirusTotal, which at the time of its scan, 6 different anti-virus vendors flagged them as suspicious.
image: D:/Desktop/malware/IntelliGraph\Dataset\Image\medium\20241224_133738_161941\1MXl1hYDdkt3953oqTo4Bg.png
By looking at the behavior analysis section in VirusTotal report, we learn that this executable is exchanging the victim’s encryption keys with the following URL: “hxxp://35[.]235[.]126[.]33:8080/new-key?os=windows&arch=386”, and downloading the desktop wallpaper: “hxxp://35[.]235[.]126[.]33:8080/image”.
Written in Go, Tunneling Traffic
Scanning the executable in Intezer Analyze also revealed that it is written in Go, packed using the UPX packer and contains a popular network tunneling open source module called gost (Go Simple Tunnel), most likely to communicate with the C2 server behind the tunneling server.
image: D:/Desktop/malware/IntelliGraph\Dataset\Image\medium\20241224_133738_161941\1f5KZds_OGr7pzp29HGvXg.png
Exfiltrating Credentials
The behavior of this malware, which includes credentials harvesting and exfiltration to a known IP address, is similar to that of the “Oski Stealer,” a known credentials stealer sold on Russian-speaking forums.
image: D:/Desktop/malware/IntelliGraph\Dataset\Image\medium\20241224_133738_161941\17gVVDHuHMu2bAA82qedQ.png
Dynamic Analysis
We executed the payload in a sandboxed environment and found that the flow of the malware was as follows:

Requesting a 64-byte encryption key and readme message from “hxxp://<endpoint>/new-key?os=<os>&arch=<cpu architecture>”
Encrypting the victim’s files using the server-generated key
Downloads and sets the desktop background image to an image from “hxxp://<endpoint>/image”
Creates a readme.txt file on the victim’s desktop

Ongoing Campaign
During our research into the attack, we discovered that the attacker had been using a staging server with a particular IP address (35[.]235[.]126[.]33) However, the IP address was eventually shut down. Using AlienVault, we were able to determine that the IP address was associated with the hostname “cookie-coin[.]xyz”.
As we continued to study the domain, we discovered a potentially relevant subdomain: “cia.cookie-coin.xyz.” The URLs on this subdomain were the same as those on the main domain. Interestingly, the threat actor had also uploaded newer versions of the malware that made HTTP requests to the domain instead of the IP address. Since this attack is ongoing and the attacker has not yet uploaded updated versions of the packages published on NPM and PyPi, we are continuing to monitor for any new activity.

Attacker’s Profile
As we continued our investigation into the attacker, we found several indicators that suggest the attacker is Russian. For example, the Telegram user account associated with the attack has a Russian phone number, and the attacker was able to respond to our messages in Russian. However, it is important to note that this information has not been confirmed and should be treated with caution.
image: D:/Desktop/malware/IntelliGraph\Dataset\Image\medium\20241224_133738_161941\19_HzjaQl59P7TfD3_rpmiQ.png
Additionally, we found a GitHub account that might belong to the attacker, as one of the repositories is linked to one of the suspicious domains “cookie-coin[.]xyz”
image: D:/Desktop/malware/IntelliGraph\Dataset\Image\medium\20241224_133738_161941\1a0nHmXiCEIZO8OX69stEzA.png
Furthermore, we have discovered that the Crates user “https://crates.io/users/cookie-for-pres" has a very similar GitHub user account and uses the same profile image. While this is not a strong link, we are continuing to monitor the activity of this user account in the Rust ecosystem.
Conclusion
These attacks demonstrate again that cyber attackers have been focusing their attention on the open-source package ecosystem; We believe this trend will only accelerate in 2023, forcing developers and organizations to put the proper controls in place.
The struggle against threat actors who seek to poison our software supply chain ecosystem continues to be a formidable challenge, as attackers constantly evolve and employ new and unexpected techniques.
As we see an increase in different attacks on the ecosystem, it is critical to expedite information flow on these attacks across all parties involved (package registries, security researchers, developers) to protect the open-source ecosystem against those threats.
By collaborating, we can stay ahead of attackers and fight against software supply chain attacks.
