The SCS team has been closely monitoring a threat actor under the label PYTA31, in a recent attack detected by our ML power engine. PYTA31 was found distributing the “WhiteSnake” malware. This attack was also reported a few days ago by JFrog’s security researchers.
In the past few days, our obfuscation detection engine successfully uncovered several additional packages linked to this threat actor. Some of these packages remain accessible on the PyPI repository posing a potential risk to unsuspecting users.
Dissecting the Malicious Payload
The malicious code was embedded inside the package, base64 encoded, which also allowed the attacker to ship the binary within the code. After installation on the victim’s machine, the OS-specific code executes the corresponding payload. On Linux-type OS an exec command executes a simple python script, whereas, on a Windows-type machine, a more complex “WhiteSnake” malware executable is created and executed.

EXE Deep Dive
The malware’s various classes and methods served distinct purposes: setting up the execution environment (Class ap), capturing system information (Class cU1zCp), and managing resources (Class cXcv).
These methods were responsible for tasks such as directory creation, new process initiation, and garbage collection (GC.Collect()).
Additionally, they gathered information about the user’s system, including username, machine name, IP location, screen resolution, CPU and GPU data, local disk size, memory, computer manufacturer and model, running processes, loaded DLLs, and the title of the active window.
The malware also included a method for capturing a screenshot of the entire screen.
The malware has eight different Command and Control (C2) servers listed inside it to maintain communication with the attacker's infrastructure and elongate its life if one server is taken down. This ensured resilience in case one server was compromised.
The Remote Access Tool (RAT) (Class dMKDNw) listened on a local HTTP server for incoming commands, executed them, and returned the results to the caller. The malware also manipulated files and directories (Class dQMxB_), deserializing XML data and processing it accordingly.
The malware implemented a Tor expert bundle (Class f1T0IP) to obfuscate its communication channels further. This set of tools allowed the malware to run a Tor network for secure communication. Furthermore, the malware utilized various techniques such as string manipulation, date-time calculations, file compression, file handling (Class fFFOw), and a wrapper for application settings (Class fxQ).
Anti-debugging and anti-virtualization measures were implemented within Class kjr, which terminated the process if it detected a virtual machine, sandbox environment, or an attached debugger. Another method in this class ensured the malware’s persistence by copying the executable to the user’s AppData folder and creating a shortcut in the startup folder.
Conclusion
Our ML engine successfully revealed and thwarted part of the malicious “WhiteSnake” campaign. This incident highlights the critical need for vigilance when it comes to open-source packages. While PyPI and other package managers offer valuable resources for developers, it is essential to vet any package thoroughly before implementing it in your projects.
Moreover, investing in robust security measures, like our machine-learning malicious obfuscation detection engine, can help identify and neutralize potential threats before they wreak havoc. Don’t wait for the next attack; take action now to secure your software supply chain and protect your valuable data.
