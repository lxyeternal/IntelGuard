Detecting Malicious Code with ChatGPT
Our research team started its journey with challenging ChatGPT to detect if the code snippets we send are suspicious to contain malicious code.
As a starting point, the playground app https://platform.openai.com/playground was a great place. We created a prompt with instructions to respond “suspicious” when the code contains malicious code. Otherwise “clean”.
You are an assistant that only speaks JSON. Do not write normal text. You analyze the code and result if the code is having malicious code. simple response without explanation. Output a string with only 2 possible values. “suspicious” if negative or “clean” if positive.
The model we used is “gpt-3.5-turbo” with a custom temperature setting set to 0 as we wanted less random results.

Down The Rabbit Hole
Sometimes it is easy to forget that the AI model we use here is just “another word generator statistics engine” with some context behind it. For example, if I ask you, the reader, to complete the prompt “The sky is b” you and everyone you know will probably say “Blue”. The probability is how the engine is trained, it’s basically a statistics engine that will complete the phrase based on what others might have said. The AI doesn’t know what the “sky” is, it has never seen one. It doesn’t know what the color “blue” looks like, it has no eyes as it has no friends nor taste of food that it can describe so vividly.
The second issue is that the model was never thought the answer “I don’t know”. Since everyone on the internet has some answer to offer, even if you ask something ridiculous, the model will always spit an answer even though it might be complete gibberish as it will try to “complete” the text by the context behind it.
The third part consists of the way those models are fed data, they always get it through one pipeline, as if one person is feeding it the data. By that it can’t differentiate between different people, its world view consists of one person only. So if this person says something is “Immoral” and then they say it is “Moral”, what should the AI Model believe?
So, what does it have to do with GPT restrictions? Well, there aren’t really any restrictions at all. The way that the creators restrict the model is by instructing it to “behave”, and this is used as a context for your next query… But you can override it with the most ease like the community has already demonstrated with DAN¹.
Major Security Pitfalls
Pitfall #2: Manipulation of response Format.
Aside from manipulating the result of the returned content, the attacker may manipulate the response format, breaking the system or leveraging a vulnerability of an internal parser or a deserialization process.
Decide whether a Tweet’s sentiment is positive, neutral, or negative. return an asnwer in a JSON format: {“sentiment”: Literal[“positive”, “neutral”, “negative”]}.

Pitfall #3: Manipulation of response Content.
When using LLMs we can easily “enrich” an interaction with a user, making it feel like they are talking with a human when contacting support or filling some online registration form. For example:
Bot: “Hey! What’s your name and where are you from?”
User: “[USER_RESPONSE]”
The system will then take the user response and send the request to an LLM to extract the “first name”, “last name” and “country” fields.
Please extract the name, last name and country from the following user input. Return the answer in a JSON format {“name”: Text, “last_name”: Text, “country”: Text}:
```[USER_RESPONSE]```

Summary
Our experiment with LLMs has shown that language-based AI tools can be a powerful resource for detecting malicious code. However, it is important to note that these tools are not completely reliable and can be manipulated by attackers.
Call for action for cyber solutions to protect us from AI manipulations as we move towards a more AI-driven future, we see processes become more automated and controlled by AI.
Imagine a firewall solution integrating AI tool to process inputs and generate rules on the fly for example. There’s a new attack surface coming with this cool new technology.
Remember, LLMs are like another person, packages together with the good and the bad. As humans, they are vulnerable to Social Engineering. Every input from them needs to be verified before it is processed.
