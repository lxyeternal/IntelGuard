# Task
Extract structured knowledge from malicious code analysis reports to build a knowledge base for enhancing automated detection systems.

# Objective
The extracted knowledge will be used to:
1. Build a knowledge graph connecting malicious code patterns with expert reasoning
2. Enable detection systems to understand WHY code is malicious, not just pattern matching
3. Support context-aware malware detection through expert knowledge transfer

# Input
Malicious code analysis report:
{REPORT_TEXT}

# Extraction Requirements

## 1. Package Information
- package_name: exact name of malicious package
- package_version: version number(s) affected
- platform: PyPI/npm/RubyGems/etc
- discovery_date: when discovered
- package_type: claimed functionality (SDK/library/tool/etc)

## 2. Malicious Code Snippets
For each code snippet mentioned in the report:
- code_snippet: exact code as shown in report
- language: Python/JavaScript/Shell/etc
- location: where code appears (e.g., __init__.py, postinstall, setup.py)
- malicious_behavior: what this code actually does
- execution_trigger: when/how code executes (install-time/import-time/runtime)

## 3. Malicious Behaviors
List all malicious actions performed:
- behavior_type: credential_theft/data_exfiltration/persistence/lateral_movement/etc
- technical_description: how it's implemented
- target: what it attacks/steals (files/credentials/network/etc)
- impact: consequence of this behavior

## 4. Attack Chain
Complete sequence of attack steps in order:
- step_number: order in sequence
- action: what happens at this step
- technical_detail: how it's implemented
- purpose: why attacker does this step

## 5. Detection Indicators
Technical indicators for detection:
- file_paths_accessed: sensitive files read/written
- network_behaviors: external connections, domains, data transmission patterns
- suspicious_api_calls: unusual API usage patterns
- anomalous_patterns: behaviors unusual for this package type
- tool_usage: malicious tools downloaded/used (e.g., TruffleHog)

## 6. Expert Reasoning (CORE KNOWLEDGE)
**THIS IS THE MOST CRITICAL SECTION**
Extract the expert's reasoning process about why this is malicious:

- suspicious_element: specific code/behavior being analyzed
- expert_judgment: malicious/suspicious/high-risk
- why_suspicious: expert's explanation of why this is malicious
- normal_expectation: what legitimate packages of this type normally do
- context_violation: what convention/common-sense this violates
- reasoning_logic: expert's step-by-step reasoning process
- red_flags: specific indicators that raised suspicion
- confidence_level: how certain the expert is
